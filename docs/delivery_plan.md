# 交付计划

2026-10-18 精简：已完成的历史和每行的验证记录移到 [archive/delivery_plan_2026-10-18.md](archive/delivery_plan_2026-10-18.md)；更早的在 [10-13 版](archive/delivery_plan_2026-10-13.md)、[10-05 版](archive/delivery_plan_2026-10-05.md)，各批验收记录都在 [archive/](archive/)。

## 目标

1. **Agent 接入（主线）**：同一个 ServerBody 和同一组 MCP 工具，可以选用 Claude Code、Codex、DeepSeek Harness（dsh），以后再加原生 API（v0.1 之后）。dsh 的需求最高，优先做。
2. **Mod 适配：接口加示例**：核心模组开放适配接口，我们自己做 2～3 个示例；其他 Mod 由使用者按接口自己适配。适配器做成装上就能用的附属模组。
3. **多版本、多加载器**：按需求再做，不提前铺开。10-21 有了第一个需求：用户要支持的整合包「香草纪元：食旅纪行」是 1.20.1 Forge（见 [1.20.1 Forge 移植](forge_1201_port.md)）。

## 还没解决的

- **持续陪挖**：10-12 按试玩反馈改成跟着走时也扫玩家 16 格内的矿（方案 A），改后还没试玩；修正记录见[陪挖验收](archive/companion_mining_validation.md)。
- **Node 24.15**：在 Windows 上有一次没定位的原生退出（0xC0000409），用别的 Node 24 加 `-NodePath` 绕开；安装包带的是官方 zip 版 Node（见[打包和发布](release.md)）。运行端整套测试偶尔有一个文件整体失败，单独重跑都过，原因没查清。
- **评审遗留**（见 [评审修复记录](archive/boundary_review_fixes.md)）：R6 只做了背包物品的观察降级，容器格子和地上物品还没有。
- **托管途中死亡**：WebUI 启动的托管（`start-server-play.mjs --wait`）等角色原地复活后自动重新接管，告诉 Agent 死因和死的地方；命令行不带 `--wait` 时要重新启动托管。隔离服复活脚本改成死后等 3 秒再复活后还没跑。
- **提示词和工具瘦身**（10-12，[工具整理方案](tool_consolidation_plan.md)、[启动提示词瘦身方案](prompt_slimming_plan.md)）：还没用真实模型系统地试过。
- **实测脚本靠本地夹具**：隔离服实测依赖本机存档、备份和端口，没有 CI。
- **建筑**：屋顶最窄的屋脊和墙角竖放的柱子会剩一些；不会搭脚手架走廊，大房子要多叫几次；10-12 试玩盖屋顶时总下来，屋顶策略另外设计（分支 `build-design` 在做）。
- **单人模式**：只支持开局域网后接管（[单人模式](singleplayer_design.md)）；不开局域网的暂停处理不做（用户 10-13 定）。单人世界存档名只差符号会映成同一个世界标识，不修（改规则会让已有世界的记忆接不上）。
- **状态收拢**：[状态归属](state_ownership.md)最后 6 条建议做了第 2、4 条；第 1 条（姿态记录只由运行端判断）等以后改姿态规则时一起收，第 3、5、6 条不急。

### 更新方式还没收尾的

[更新方式](update_design.md)按设计做完，测试版已发到 0.0.5：

- **正式版叫 0.1.1**（用户 10-15 定）：以前所有 jar 都写的 0.1.0，现在靠“要装的版本低于 0.1.0 时把 0.1.0 当旧版”（`LEGACY_VERSION`）区分；正式版跳过 0.1.0 直接发 0.1.1，还装着旧 0.1.0 jar 的人会被当成需更新，不用等朋友都更新一次。
- **没有 WebView2 的电脑**：安装时下载微软引导安装器补装、补装失败时 mcbot.exe 退回浏览器打开，两条路线都没在缺 WebView2 的机器上试过。
- **从安装版真正托管一次**：安装版目前只验证了安装、更新、插件页装模组；还没有从安装版开配置、连世界、用真实模型托管。这就是原来“在干净环境从头安装一遍”的演练。
- **`publish.mjs --ssh` 直连上传不是原子的**（10-18 核对文档时发现，代码没改）：不另放下载服务器时，`app/`、`core/`、`plugins/` 的文件直接 scp 到最终文件名，只有 `index.json` 先传 `.tmp` 再改名；传到一半断开会在站点上留下半截文件，下次发布因同名大小不同而停下，要手动删。可以照 `--files-ssh` 那样先传 `.part` 再改名。
- **以后**：在 hello 里带上核心版本、由运行端拒绝不匹配的（现在只在启动托管前读 mods 里的 jar）；YSM 模型从服务器下载（用户 10-15 定先不做，也不分发第三方模型）。

### 想做、还没设计的

- **自主性**（用户 10-12 提的：Agent 要有一些自主性，比如生存时有“今日安排”，自己想干点事）。我的建议（还没设计）：主动程度做成 WebUI 里的档位（只听指令／提建议、答应了才做／在玩家身边做小事／玩家忙或挂机时完全自主），默认提建议；早上（已有的 time 事件）按背包、家里情况和玩家说过的话列两三件当天想做的事，安排存在运行端（像 places 那样按世界存，压缩、重启后还在）；玩家一段时间没吩咐时（接已有的空闲提醒）按安排做一件小事。要注意：每次主动行动都是一轮模型调用，要有频率上限；不用玩家箱子里的东西、不拆东西、离开玩家时保护顾不到，要由程序保证；记得昨天的安排和玩家喜好最终要长期记忆。用户 10-12 同意先做提示词瘦身、试玩之后再出设计。
- **远处视野**（用户 10-12 提的：开了很远的视野、装了 Voxy，说“你看这边远处有片丛林，去砍树”时 Bot 怎么办）。Bot 是服务端里的玩家实体，没有客户端，自己不渲染画面；Voxy 的远景只在用户客户端，服务端拿不到。服务端有的是已加载区块（局域网下大约跟房主的渲染距离走）、玩家的朝向，和按种子算出的任意位置的生物群系（不用加载区块）。方案（都还没做）：
  - 顺着方向看：从玩家眼睛沿视线（或水平朝向）取样，已加载范围内给到方块级（多远、什么地表、有没有树），更远只给生物群系；上限复用服务端视距和 2000 格，不另起数字。要改核心。
  - 截用户的游戏窗口：旧 `mcp-server` 做过 `player-view`（只截用户确认过的那个 Minecraft 窗口，带光影和远景），可以搬到运行端，不改核心。限制：Agent 要和游戏在同一台电脑；模型要能看图；每张图约 1000 多 token；图里的东西没有坐标，模型估距离不准，所以要和上一条一起用（图认出是什么，取样给出在哪）。
  - Bot 自己视角的渲染（旧 `look`，prismarine-viewer 无头浏览器，只画附近几个区块、默认材质、模组方块没贴图，还要从服务端导出区块数据）：看不了远处，不推荐。

**Bot 为什么不用创造模式干活**：创造模式下挖方块不掉落、不消耗耐久，放方块和吃东西不消耗物品，不会饿、不受伤。现在每个动作都靠“背包前后变化、掉落物、耐久、血量”核对结果，到了创造模式这些都不成立，采集、合成、烧炼、建筑、进食、自卫、保护的回执会全部算错或报未知。要支持就得为创造模式另写一套执行和核对，工作量接近重做一遍，而且创造模式本身用不上这些功能，所以不做；Bot 一直保持生存。
