# 建筑设计能力

2026-10-15 用户提出：让 Agent 学会**自己设计**房子，不只是照着别人的蓝图盖。分支 `build-design`，和 main 分开。

## 为什么不只是整理成 skill

模型盖不好房子卡在三处：不知道什么好看（审美和规律）、要逐格写坐标（空间推理容易错，弱一些的模型更明显）、看不见自己设计的样子（没法自己改）。一份文字说明只解决第一处。所以分三层：

| 层 | 做什么 | 状态 |
|---|---|---|
| 知识 | 设计流程、零件用法、通用手法、看图检查清单、各风格的材料和形体，放在 `client-runtime/building-guide.md`，模型用 `blueprints` 的 `guide` 动作按需取（三家 Agent 都能用，不占启动提示词） | 10-15 完成：通用手法和 9 张风格卡按 12 个投影的统计和画图改写（见下文「收集的投影怎么用」） |
| 表达 | 零件和材料表：模型写二三十行描述一栋房子，运行端展开成几千格；换风格只换材料表和屋顶参数 | 10-15 完成（离线） |
| 反馈 | 画图：两张斜 45° 立体图、每层平面图，加文字平面图给看不了图的模型；改蓝图不用整张重写 | 10-15 完成（离线） |

旧 Mineflayer 时代有过这一套（私有仓库的 minecraft-building skill、`render-blueprint`、`edit-blueprint`），小克自己设计的现代平顶别墅得过 8/10；换成 ServerBody 后没搬过来，这次搬回来并加上零件。

## 零件（`client-runtime/src/blueprints.ts`）

`build` 和 `blueprints` 的 save/render 收同样的 `shapes`、`blocks`、`palette`，最后都展开成格子交给服务端，服务端代码不变。

- `palette`：按用途起名的材料表，任何写方块的地方写 `@名字` 或 `@名字[属性]`。
- `box`：四面墙，`floor`／`ceiling` 填底层和顶层里面，`frame` 加底圈和顶圈横梁、四角和每 `pillarEvery` 格的竖柱。
- `window`：同一面墙上的开口，`facing` 朝外；`recess` 玻璃退一格、`sill` 窗台（楼梯倒放贴墙、台阶放上半）、`trim` 一圈框。
- `door`：一或两格宽，门朝里放（从外面放的朝向），双开门铰链在外侧；门上那格给 `air`，服务端把它当门的上半的位置（BuildTask 允许门上半位置是 air 目标）。
- `stairs`：朝 `facing` 每格升一格，每级上面清两格（会在上层楼板开楼梯洞），`support` 填实下面。
- `roof`：`style` gable／hip，`pitch` 1（楼梯）／0.5（台阶，上下半交替）。山墙统一按“每列屋面下面填到上一层”算，原来的双坡结果不变。`trim` 是收边：屋檐那一圈和两端山墙边（四坡是屋檐和四条斜脊）换成另一种楼梯（缓坡用它的台阶），屋脊两端跟着换；参考作品几乎都这样做。`rings` 只铺外面几圈（没有屋脊和山墙）：两层之间的腰檐、陡屋顶下面再加一圈缓檐（10-15 试设计时三个模型都在手搓腰檐，只用缓坡盖大屋顶会像个扁盖子）。
- `line` 和零件里的原木、柱子类按走向自动设 `axis`（状态里写了就不动）。
- 每个零件先估格数，超过一次 build 的 4096 格就拒绝，不先生成几百万格。

限制：开着的活板门（百叶窗）服务端不核对 `open`，放不出来，所以没有百叶零件；`pitch 0.5` 的山墙在上半台阶下面会留半格缝；楼梯转角画图时都按直的画（游戏里放下去会自己连成转角）。

## 画图（`client-runtime/src/render.ts`）

照搬旧的 `mcp-server/src/vision/voxel-render.ts`（正交投影、深度缓冲、平面图切在地板上两格），区别：

- 不带 prismarine-viewer（安装包会多几百 MB）和原版贴图：`scripts/render-assets.mjs` 在开发时从 mcp-server 装好的 prismarine-viewer（MIT）读 1.21.1 的方块模型，只留形状和每个面的平均颜色，生成 `client-runtime/render-assets.json.gz`（约 80 KB，随包带）。换 MC 版本或改生成方式时重跑这个脚本。
- 不认识的方块（模组的）画成品红色方块。
- PNG 自己编码（zlib + 格式要求的 CRC），不依赖 pngjs。
- 结果同时给文字平面图（`#` 墙、`W` 窗、`D` 门、`/` 楼梯…），坐标能直接核对，也给看不了图的模型用。工具结果里带图片（MCP image content）；Claude Code 能看，Codex 和 dsh 能不能看还没试，`image:false` 只要文字。

还没做：画世界里实际盖出来的样子（要服务端读一块区域的方块）。

## 改蓝图（`blueprints` 的 `edit`）

`replace` 换材料（只写名字就全换，facing、half 这些在新方块也有的才保留，靠 render-assets 里的默认属性判断；写了属性只换对得上的）、`within` 限定范围、`remove` 删格子、`set` 改几格；`saveAs` 另存或 `overwrite`。最小角变了会说坐标挪了多少。

## 收集的投影怎么用

用户 10-15 收集了 12 个 `.litematic`（来自教学网站，主办方允许下载和二次分发）。用途：
1. 提炼规律和风格卡（10-15 完成）：用旧导入器解码、换成 1.21.1 的方块，从外面往里灌空气找出外皮，按朝向分成墙面和屋面，统计材料分工、竖柱和柱距、楼层、屋檐外伸、屋顶用料、玻璃占比、每个朝向墙面的前后层数，再逐个画图对照。写进 `building-guide.md` 的主要结论：
   - 墙面不平：每个朝向的外墙都有 3～12 层前后变化，外皮里三到四成是楼梯、台阶、活板门、栅栏；
   - 屋顶几乎都换一种材料收边（木屋顶配石砖边、深色瓦配白色屋脊或木头边），于是给 `roof` 加了 `trim`；
   - 几乎都坐在一圈 1～2 格的石砖、圆石或平滑石小路／地台上，寺院坐在 2～3 层石台上；
   - 出檐 1～2 格（日式、拉面馆 3～5 格），层高 4～5，原木柱每 4～6 格；
   - 外墙玻璃 5～17%（日式几乎不用，石屋、现代 20～30%）；墙最多的那种方块只占外皮两到三成，小房子 8～20 种方块，细节多的 35～70 种。
   风格卡 9 张：日式、乡村木屋、石砖小屋、现代、西部酒馆、木构大厅、集市小摊、庭院和大树（从投影来），每张写成能直接用的材料表和零件参数。统计脚本和图只在开发机上（不进仓库），原投影没有放进仓库。
2. 考试题：只给文字题目让 Agent 设计，和原作的图放一起由用户打分。
3. 施工测试：转成蓝图用 `server-build-smoke.mjs --house` 测 build 放得准不准。

不建议把它们当作能直接盖的蓝图放进 Bot 的蓝图库，模型会倾向照抄。

## 真实模型试设计（10-15）

走托管驱动器（产品路径），隔离服 ServerBody，同一句请求从驱动器窗口发：日式两层小屋，一楼门厅、厨房、吃饭的地方，二楼卧室，正门朝南，不超过 17×17，只设计不盖。四个模型：Claude Opus 5.5（medium）、Sonnet 5.5（high）、Haiku 5.5（high）、dsh DeepSeek-V41-Flash（high）。每个 3～8 分钟；Claude 每次 $0.04（Haiku）～ $0.97（Opus）。

- 四个都自己找到 `blueprints guide` 和日式风格卡，都用零件和材料表写设计、用了屋顶收边。
- 第一轮暴露的问题：
  - 三个 Claude 都只画一次图就交给玩家，没按清单改；
  - 都跟玩家说「图在窗口里」——玩家看不到图；
  - 只用缓坡盖大屋顶，像个扁盖子，腰檐都是手搓的；
  - dsh 写了旧方块名 `grass_path`，文字结果里没提示（dsh 是唯一改了几轮的）。
- 改了：
  - 画图结果第二行写明“只有你看得到，第一版一般都有毛病，按清单改了再画，再用几句话跟玩家说”；
  - 流程第 4 步同样改；
  - `roof` 加 `rings`，日式风格卡改成「陡主屋顶＋缓檐＋腰檐」；
  - save、edit、render 报出原版没有的方块名。
- 第二轮：
  - Opus 先画草稿，自己发现「二楼被檐挡得太矮」，加高再存再画，成了两重檐；
  - Sonnet 画完改了一格，并说了自己没把握的地方；
  - Haiku 把自己的检查结果和要玩家定的事说清楚了，但还是普通双坡木屋，不像日式；
  - dsh 交了双坡深瓦顶、腰檐、前廊的版本，没再写错方块。
- 四个都不再说玩家能看图。

用户看第二轮的图打分：
- dsh 8/10：上下明显分开的两段式两层，很喜欢；
- Haiku 7/10：一个整体的两层，偏近现代的日式，不错；
- Opus、Sonnet 各 4/10：屋顶、屋檐太大。用户个人不喜欢这种风格。

这两栋正是照第一次改的日式风格卡做的（深檐＋两重檐），所以风格卡又改了：
- 住宅屋顶用 pitch 1 双坡、出檐 1 格，墙要露出来；
- 两层用腰檐分成上下两段；
- 深檐、两重檐只留给寺院和店铺；
- 看图检查加一条「屋顶和屋檐是不是太大，盖住了二楼的墙」。

## 验证

- 离线：运行端 `tests/building-design.test.mjs` 13 项（材料表、原木朝向、box、窗、门、楼梯、四坡和缓坡屋顶、屋顶收边、只铺外圈、改蓝图、画图和文字平面图、设计参考的示例房子能展开、工具的 guide/save/render/edit 和报出不认识的方块）；运行端全部测试通过。
- 真实模型：见上一节（四个模型两轮）。
- `server-build-smoke.mjs --house` 的分段和清场高度改成跟着房子高度走（原来只盖到第 13 层、清到地面上 20 格）。
- 没做：模型设计的房子在隔离服实际盖完并核对（10-15 晚开了 Opus 第二轮那栋）；Codex 收图片；dsh 能不能看到图片没确认（它的设计看起来是靠文字平面图改的）；楼层识别会把地台、屋顶层也当成一层。
